The problem

AI assistants generate UI components quickly, and they often generate inaccessible ones. I wanted a real app where keyboard and screen reader behavior was built and checked by hand, not assumed.

What I did

I built Ronda with Claude as a React checklist app, then refactored it and added a light and dark theme.

In the accessibility lab I wrote a Modal, Tabs and Disclosure from scratch in React and TypeScript against the WAI-ARIA patterns. I tested them using only the keyboard, then compared them with shadcn/ui (Radix) by reading the generated and library source.

What came of it

A live, keyboard-operable app, and a NOTES.md file listing six concrete gaps between my components and shadcn/Radix:

  • Hiding background content from screen readers while a modal is open
  • Scroll locking
  • Portal rendering
  • Tab activation modes

Those are the details that separate a component that looks right from one that behaves right.
